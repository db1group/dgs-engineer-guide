# AGENTS.md — Engineering Guide DB1

## Visão geral

O **Engineering Guide** é o site estático de documentação de engenharia da DB1 Global Software,
publicado em `engineerguide.db1.com.br`. O próprio site é a documentação do produto e tem duas
seções, cada uma com menu próprio:

- **Guia** (`/docs/`) — disciplinas Engenharia, QA e DevOps: o "jeito DB1", boas práticas e
  avaliação de senioridade de cada disciplina;
- **Aceleradores** (`/dgs-components/`) — Golden Path, Easy Monitor, Easy Docs e Easy Connect.

O site é publicado em três idiomas: pt-BR na raiz, inglês em `/en/` e espanhol em `/es/`.

Os domínios, suas fronteiras e a ordem sugerida de implementação estão em
`.agents/maps/functional-map.md`. O objetivo, as restrições e as decisões transversais estão em
`.agents/context/discovery-answers.md`, cujas restrições prevalecem sobre inferências posteriores.

## Stack

O repositório está em migração do **VitePress 1.x** para o **Docusaurus 3.10.2**. O VitePress
gera o site em produção até o corte; toda implementação nova segue a plataforma Docusaurus.

- **Em produção (VitePress):** `vitepress` ^1.1.3; configuração em `.vitepress/config.mts`
  (`srcDir: "src"`, `cleanUrls: false`) e menus de cada idioma declarados à mão em
  `.vitepress/pt.ts`, `en.ts` e `es.ts`; tema em `.vitepress/theme/` (`style.css` e MathJax via
  CDN em `index.ts`); busca `local` do VitePress.
- **Plataforma-alvo (Docusaurus):** `@docusaurus/core` e `@docusaurus/preset-classic` 3.10.2
  (React 19) com `blog: false` e sem `versions.json`; configuração em TypeScript
  (`docusaurus.config.ts`); i18n com `defaultLocale: 'pt-BR'` e locales `pt-BR`, `en` e `es`;
  sidebar `autogenerated`; `@easyops-cn/docusaurus-search-local` 0.55.3;
  `@docusaurus/plugin-client-redirects` 3.10.2; `remark-math` + `rehype-katex` (KaTeX).
- **Comum:** Yarn 4.5.3 (`.yarn/releases/yarn-4.5.3.cjs`, `nodeLinker: node-modules`), Node.js,
  GitHub Actions e Amazon S3 (website hosting).

## Comandos

Os scripts de `package.json` são a referência dos comandos. Com o VitePress:

| Comando | Uso |
|---|---|
| `yarn install --immutable` | instala as dependências (forma usada no CI) |
| `yarn dev` | servidor local de desenvolvimento |
| `yarn build` | build estático em `.vitepress/dist` |
| `yarn preview` | serve o build localmente |

No Docusaurus, o build é gerado em `build/`. O repositório não tem lint nem testes automatizados:
a validação é o build (com `onBrokenLinks: 'throw'` no Docusaurus) somado à comparação lado a
lado com o site atual antes do corte.

O build não depende de variáveis de ambiente. A publicação usa credenciais AWS via OIDC com a
variável de repositório `vars.AWS_DEPLOY_ROLE_ARN` do GitHub.

## Restrições globais

- O conteúdo das páginas não é reescrito nem revisado. Exceções: tradução do bloco DevOps para
  `en`/`es` e correções de link e de imagem. O saneamento para MDX 3 altera apenas sintaxe, e
  metadados de frontmatter (`sidebar_label`, `sidebar_position`, `slug`, `unlisted`) não contam
  como conteúdo.
- A busca é local. Algolia DocSearch é o plano B, acionado apenas se
  `@easyops-cn/docusaurus-search-local` deixar de acompanhar as versões do Docusaurus.
- Versionamento de documentação, blog e demos React ficam fora do projeto.
- A hospedagem é o bucket S3 `engineerguide.db1.com.br` (região `us-east-1`), publicado com
  `aws s3 sync`, sem CloudFront. O passo de invalidação comentado em
  `.github/workflows/prod-deploy-app.yaml` permanece comentado.
- O site não tem analytics nem telemetria.

## Convenções

- **URLs de produção:** o formato `<caminho>.html` é preservado (`trailingSlash: false` no
  Docusaurus, `cleanUrls: false` no VitePress). O S3 website hosting sem CloudFront só serve rota
  que corresponda a um objeto existente, por isso URLs sem `.html` retornam 404 ao recarregar ou
  compartilhar — o histórico de tentativas está nos commits `142569a`, `b8db5b0`, `64bd143` e
  `03f836e`. Nenhuma cópia sem extensão é publicada.
- **Caminhos e nomes de arquivo:** prefixos numéricos dos arquivos (`1-...` a `10-...` em QA,
  `0-...` a `6-...` em DevOps) fazem parte das URLs e são preservados. O S3 diferencia
  maiúsculas: a caixa dos nomes de arquivo é mantida (ex.: `SOLID.md`).
- **Redirecionamentos:** toda URL publicada que deixar de existir ou mudar de caminho recebe
  redirecionamento com `@docusaurus/plugin-client-redirects`.
- **Páginas fora do menu:** `technical-agreements.md` (três idiomas) e
  `dgs-components/easy-monitor-en/` ficam publicados com `unlisted: true`, acessíveis por URL.
- **Busca:** `@easyops-cn/docusaurus-search-local` com `language: ["pt", "en", "es"]`, indexando
  as duas seções.
- **Fórmulas:** `remark-math` + `rehype-katex` com a folha de estilo do KaTeX; blocos `$$ ... $$`.
- **Assets:** servidos da raiz do site (`/img/...`, `/assets/ebooks/...`) e referenciados por
  caminho absoluto; referências relativas que atravessam `public/` (ex.:
  `../../../public/img/...`) são convertidas para `/img/...`.
- **Identidade visual:** título `Engineering Guide`, logo `/img/style/logo.png`, favicon
  `/img/favicon.ico`, link GitHub `https://github.com/db1group` e item de navbar "Radar de
  tecnologia" (`https://techradar.db1.com.br/`) traduzido nos três idiomas; seletor de idioma com
  os rótulos `Português`, `English` e `Español`; footer apenas com o copyright DB1 Global
  Software. O tema do Docusaurus é o port de `.vitepress/theme/style.css` para o CSS customizado
  do tema clássico.
- **Página inicial:** página do tema clássico em `src/pages/` reproduzindo o hero (DB1 Global
  Software, "Guia de engenharia", tagline, ações "O Guia" e "Nossos Aceleradores") e as três
  features (Radar de tecnologia, Easy Monitor, Easy Docs), traduzidas pelo i18n do Docusaurus.
- **Publicação:** `prod-deploy-app.yaml` publica o build em duas passadas de `aws s3 sync`:
  primeiro os assets com nome em hash, com cache longo e imutável; depois o HTML e os demais
  arquivos, com cache curto. `/assets/ebooks/` não tem hash e fica fora do cache imutável. Com
  `--delete` e sem CloudFront, HTML com cache longo faria clientes pedirem assets já removidos.
- **Node.js:** 22 LTS em `.nvmrc`, `.node-version` e `actions/setup-node`, com
  `engines.node: ">=22"` no `package.json`.
- **Dependências:** Yarn 4.5.3 versionado em `.yarn/releases`; o CI instala com
  `yarn install --immutable`, e `yarn.lock` é versionado.
- **Corte da migração:** a publicação no Docusaurus acontece após a comparação lado a lado com o
  site atual (páginas, menus, idiomas, imagens, busca, URLs `.html` e redirecionamentos); em
  seguida, `.vitepress/` e as dependências do VitePress são removidos.
- **Codificação:** UTF-8 sem BOM e fim de linha LF, preservando todos os acentos.
- **Documentação de contribuição:** `README.md` na raiz, em pt-BR, explica como rodar o site
  localmente, como adicionar ou traduzir uma página e como a publicação acontece; é atualizado na
  mesma mudança que altera o fluxo de autoria ou de publicação. ADRs, Storybook, Swagger/OpenAPI e
  coleções Postman não são mantidos.

## Estrutura de `.agents/`

- `.agents/context/` — memória da descoberta funcional: objetivo, escopo, restrições e decisões
  transversais validadas (`discovery-answers.md`).
- `.agents/maps/` — mapas de navegação do projeto; `functional-map.md` identifica os domínios, suas
  evidências, dependências e a ordem sugerida de implementação.
- `.agents/skills/` — skills carregadas sob demanda pelo agente, a partir do `description` no
  frontmatter de cada uma. Reúne skills de negócio (um domínio do guia ou um acelerador) e skills
  técnicas (transversais, como autoria de páginas e plataforma).

## Precedência das skills

- Antes de criar ou editar arquivos, ou de implementar qualquer funcionalidade, verifique se uma
  skill de `.agents/skills/` governa o caso — pela tecnologia, padrão de código ou arquitetura
  envolvidos, ou pelo domínio de negócio, funcionalidade ou módulo em questão — e siga-a antes de
  agir.
- As skills são autoritativas e prevalecem sobre padrões inferidos do código existente.
- O corpo de cada skill indica onde vive a documentação completa do seu assunto e qual fonte
  detém a verdade, dentro ou fora do repositório; siga essa indicação a partir da skill.

## Escrita de comentários e documentação

Todo texto que vive neste repositório — comentário de código, docstring, skill, `AGENTS.md`,
README, spec, página do guia — descreve o estado atual, escrito para quem abre o arquivo hoje sem
conhecer o histórico do arquivo nem a conversa que o produziu.

- **Descreva o que é, nunca a transição.** Ao editar um texto existente, reescreva o trecho a
  partir do resultado final, como se ele sempre tivesse sido assim. Uma frase que só faz sentido
  para quem viu a versão anterior — ou o seu próprio diff — não pertence ao arquivo: o que mudou
  pertence à mensagem de commit e à descrição do pull request.
- **Negue apenas para evitar um erro plausível.** Uma negação merece seu lugar quando um leitor
  competente de fato tentaria a alternativa e a frase diz por que ela falha, protegendo uma
  mudança futura. Contraste com a versão anterior, com uma alternativa que ninguém tentaria ou com
  o que o código já mostra é ruído que custa a atenção do leitor.
- **Faça a poda antes de concluir a tarefa.** Releia os textos que você criou ou alterou e corte o que
  falhar nas duas regras acima. Expressões como "não mais", "costumava", "agora é", "em vez de",
  "ao invés de", "diferentemente de" e "sem precisar" são os sintomas habituais — mantenha apenas
  as que sobrevivem à segunda regra.

Uma exceção: quando o assunto do texto **é** uma mudança — mensagem de commit, descrição de pull
request, spec de uma unidade de manutenção, changelog — a transição é o conteúdo. A regra proíbe
narrar a *edição do texto*, nunca a mudança de que o texto trata.
